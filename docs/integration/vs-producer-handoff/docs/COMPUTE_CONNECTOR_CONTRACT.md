# Owner runtime connector

No compute is provisioned by this feature. Ash must sign in with a verified WorkOS identity and a current deployment-owned owner grant, and configure that account's existing HTTPS runtime origin and bearer credential. Connections are account-owned, never shared implicitly. Existing UTILITYSIM_RUNTIME_* settings and worlds are untouched.

`/api/compute` query actions:

| Action | Method | Body/query | Response |
|---|---|---|---|
| connection | GET | none | `{connection:null}` or `{connection:{endpoint,revision,credentialConfigured,updatedAt}}` |
| connection | POST | `{revision,endpoint,credential:{operation:"keep"|"replace"|"clear",value?}}` | masked connection |
| test | POST | `{}` | `{connected:true,sources:[...]}` only after approved ready runtime source verification |
| worlds | GET | offset=0, limit=25 (max 50) | runtime `{worlds,total,offset,limit}` |
| create | POST | `{commandId,sourceId,sourceRevision,name,start,configuration}` | runtime world status |
| status | GET | id=32 lowercase hexadecimal characters | runtime world status |
| advance | POST | id=32 lowercase hexadecimal characters, `{through:"YYYY-MM-DD"}` | runtime status |
| observations | GET | id=32 lowercase hexadecimal characters, start/end canonical dates | runtime observations |
| events | GET | id=32 lowercase hexadecimal characters, before=sequence, limit≤50 | runtime event journal |
| storms | GET | id=32 lowercase hexadecimal characters, before=date, eventsBefore=sequence, limit≤50 | runtime storm inspection |
| storms | POST | id=32 lowercase hexadecimal characters; exact schedule/cancel command from hosted runtime contract | runtime result; requires world.advance |
| sentiment | GET | id=32 lowercase hexadecimal characters; optional premiseId, before=canonical date, newsBefore=positive int64, limit=1–50 | runtime administrator sentiment history/news |
| sentiment | POST | id=32 lowercase hexadecimal characters; exact news schedule/cancel command from hosted runtime contract | runtime receipt; requires world.advance and same Origin |

Sentiment queries accept safe premise identifiers of at most 200 characters, valid canonical dates, and positive integer cursors up to 9223372036854775807. Duplicate query fields and unsafe premise paths are rejected. Mutation bodies pass unchanged to the runtime's strict news command validator; browser authority is never forwarded. Every sentiment request first checks the principal-owned world status and current source/town grant.

The setup catalog currently advertises physical-setup/4 and retains `configuration.supportedVersions` entries for physical-setup/2, /3 and /4, each containing its own schemas and defaults. Draft validation selects the explicitly supplied configuration.schemaVersion and never adds later groups. World-only v1 payloads remain world-only. Meter channel shares must total 100 within 1e-8 even when the overlay is disabled; enabled cashflow requires enabled household finances. Existing saved records are not migrated or rewritten on listing.

Errors generated by the gateway contain both `detail` and `error`. Runtime errors preserve runtime `detail`. Requests need a fresh authenticated session and current grants; mutations also require the configured same Origin. Source revision must match the shell's approved catalog for create/status/advance/observations. Runtime additionally enforces principal ownership. Browser identity headers are ignored; gateway sets verified principal and current grant headers.

Connector saves use owner-keyed Redis records and atomic revision compare/write. Credentials use AES-256-GCM with principal associated data and a purpose-derived key from WORKOS_COOKIE_PASSWORD. Rotating that secret requires reentering runtime credentials. Credential readback is only a boolean. Keep/replace/clear is explicit, and endpoint changes cannot carry a stored credential to another host.

Only public HTTPS DNS origins on port 443 are accepted. All DNS results are checked at request time, and the chosen address is pinned into the TLS request lookup. IP literals, private/reserved addresses, redirects and non-JSON responses are refused. TLS certificate verification and hostname SNI remain active. No arbitrary path proxy exists. Runtime request timeout is 20 seconds; request JSON is at most 64 KiB and response JSON at most 3,000,000 bytes. Large snapshots/bindings are deliberately unavailable through this gateway: the accepted snapshot is approximately 8 MB, exceeding Vercel's 4.5 MB function payload limit. Shell uses its approved pinned static map; a future authenticated large-object design requires separate work.

UI integration: include compute-connection.html/js/css in build output and owner page guards; link compute-connection.html from owner workspace UI. API entry is api/compute.js; no dynamic Vercel rewrite is needed. Existing runtime session boolean is unrelated to per-account connector state; GET connection or list actual worlds instead. Events and storms use the backend's explicit events/storms contract. Jobs/pause/import/billing remain unsupported.

## Applied profile status

Available world status includes read-only `physicalProfiles` with model version, configuration digest, separate meter/housing enabled flags, actual aggregate meter counts and realised housing count/age range/mean/retrofit statistics. It reads the registered instance without initializing profile tables or changing its availability. Disabled legacy worlds expose no invented assignments; partially configured worlds remain unavailable.

## Next acceptance: interval reads

The implemented AMI/AMR/manual adapter preserves the full measured interval independently of the collection-date query window. Integrated browser/runtime acceptance verified 1,262 manual reads collected in July 17–18 retain their July 15–18 intervals, with no unscheduled daily reads. A read collected January 30 may similarly cover January 1–31; consumers must retain that original interval without clipping or inventing daily readings. Downstream Virtual Systems recipient support remains a separate unverified acceptance gate. Register reconstruction remains unknown after a reported missing collection even if a later interval quantity is recovered. Keep these cases in Ash's fixture and recipient-processing tests before declaring delivery compatible.
