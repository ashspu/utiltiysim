# UtilitySim producer handoff

Sanitized, synthetic producer fixture and public contracts for remote recipient review. Captured artifacts were copied from the coordinator's handoff bundle into this repository from merged main `60283b932b039b5a47032c97850fd422d74a8826`. This package contains no private Virtual Systems code/audit, private QA metadata, credentials, administrative truth dump or production data. `producer-contract-audit.json` describes public producer contracts and gaps.

Start with [handoff-manifest.json](handoff-manifest.json), [expected-results.json](expected-results.json), the [observation fixture](fixtures/lantern-three-day-v2.json), and [v2 schema](schemas/utility-observations-2.0.schema.json). The fixture contains 1,698 observations across electric, gas, water and derived sewer, for 436 accepted-map premises and 1,262 real meter assets. It was captured through actual engine `export_v2`; this packaging step did not rerun the engine or access a world database. Original identities, three-day measured intervals and six-hour availability delay are retained. Binding files are illustrative recipient installation mappings; they do not create installations, commercial records or a working integration.

**Limits:** hosted observations still use legacy v1. Scheduler/transport acceptance proves durable receipt, not recipient processing, billing, ledger settlement or successful physical action. The bundled `field-world-report/1` schema is a legacy standalone contract; current field execution emits `field-ack/1` and `field-report/1` envelopes. Agree those contracts with the recipient owner before adapting. Hosted authenticated transport and further fixture slices remain gaps listed in the manifest. No provisioning, deployment, production compatibility or recipient acceptance is claimed. Ashtown remains stopped; this handoff authorizes no map construction.

`checksums.json` records SHA-256 of every package file except itself. Local `.gitattributes` prevents Git newline conversion from invalidating those hashes. The copied build script received only Ruff import ordering (I001): original script SHA-256 `2cef79645629e19874dd9ca3bc8bc6ce1d5a1cce8cbe6a834f998e66914f415e`; its revised hash is explicitly recorded in `checksums.json`. All other original bundle files retain their original bytes and recorded hashes. README and Git byte-preservation rule are additions. The script is retained for provenance; it expects an independently prepared isolated capture database and creates output files/ZIP, so it is not a recipient acceptance runner.

Review validation: all package JSON parses; all eight schemas pass JSON Schema meta-validation; the observation fixture validates against its v2 schema; fixture counts, identities, intervals, availability and the deliberately missing binding agree with expected results; complete checksum coverage matches file bytes. The copied Python script passes repository Ruff and syntax checks. These checks establish package integrity, not recipient execution.
